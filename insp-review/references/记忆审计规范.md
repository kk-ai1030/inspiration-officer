# 记忆审计规范

## 为什么要审计

测评中观察到两件事：

1. **召回 ≠ 执行**：记忆会被召回到推理里，但模型可能判断“这次不适用”而不执行。
2. **自动抽取会污染**：平台在运行结束后自动抽取记忆（`source.kind = auto_extraction`），曾把某一次提示词里的临时约束（“信息不足时不要向用户提问”）固化成置信度很高的长期规则。

## 记忆里该放什么

| 放进记忆 | 不放进记忆 |
|---|---|
| 软偏好：格式、语气、关注方向 | 硬规则（交给校验脚本 + system prompt） |
| 用“条件 → 动作”写清适用范围 | 打分准则（rubric 每次作为附件显式提供） |
| 例：“仅当生成灵感卡片时：one_line 不超过 40 字” | 例：“所有报告的表格固定四列”（范围不清） |

## 审计流程

1. 编排器 `GET /api/memory` 导出全部记忆为 `memory.json`；
2. `weekly_review.py --memory memory.json` 列出所有自动抽取的条目；
3. 用户逐条决定：
   - **保留**：确实是长期偏好；
   - **改写**：改成“条件 → 动作”格式，编排器用 `PATCH /api/memory/{id}`；
   - **删除**：临时约束或错误推断，编排器用 `DELETE /api/memory/{id}`；
4. 手写的记忆统一加标签 `manual` 和分类 `taste`，方便区分。

## 预防

调试和实验时，提示词里把临时要求写成“**仅本次任务**：……”，降低它被抽取成长期偏好的概率（这一点尚未验证，需要观察）。
