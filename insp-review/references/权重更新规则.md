# 权重更新规则（设计文档 §10c）

## 公式

$$\hat{p} = \frac{s + \alpha}{n + \alpha + \beta},\quad \alpha = \beta = 2$$

- $n$：该类型被**显式**评价的次数；
- $s$：加权正反馈之和，每条评价的贡献是 $\min(1, \max(0, w))$，即采纳 +1、改写 +0.8、追问 +0.5，否决和不重要记 0。

$$w \mathrel{+}= \lambda(\hat{p} - 0.5),\quad \lambda = 0.3$$

权重下限为 0.1，不会被调到 0，类型不会被“判死刑”。

## 三条纪律

1. **样本不足不动权重**：$n < 5$ 只记录，不提议。
2. **一次只调一个维度**：每周只提议 $|\Delta|$ 最大的那一个，其余留到下周。交叉特征样本更稀，先验要更强。
3. **所有调整都要用户确认**：提议写进 `proposals_<周>.json`，`confirmed: false`。用户改成 `true` 后才能 `--apply`，并且写入 `weights.json.history`，可以回滚。

## 例子

一周内 optimization 类有 8 条显式评价，其中 6 条采纳、2 条否决：

$\hat{p} = (6 + 2) / (8 + 4) = 0.667$，$\Delta = 0.3 \times (0.667 - 0.5) = +0.05$，提议权重 1.0 → 1.05。

## 权重怎么被使用

`weights.json.type` 只用于 insp-card 在配额截断时排序（平均分 × 类型权重）。它**不改变配额**，配额只能由用户手动修改 `state.quota`。

## v1.1 增补：多维特征、测试配置、版本与回滚

- **特征维度**：`type`（卡片类型）和 `subfield`（triage 按 `state.subfields` 关键词分组得到的子方向）。每张卡片只按它**最新的一条显式评价**计一次。每次复盘仍然**只提议 |Δ| 最大的那一个特征**。
- **参数从 `state.learning` 读取**：生产配置 λ=0.3；测试配置（`platform/apply_test_profile.py --profile test`）λ=1.0，这样一次调整的幅度足够在几天内观测到。**样本门槛 n≥5 不放宽。**
- **权重如何影响行为**：`subfield` 权重乘在 triage 粗分上（决定哪些候选进入预筛名单）；`type × subfield` 权重乘在卡片的 rubric 平均分上（决定哪些卡片拿到推送名额）。两处都是确定性计算，记录在 `runs/<run_id>/triage.json.ranked` 和 `selection.json` 里，可以用 `platform/learning_check.py` 换一份权重**反事实重放**。
- **版本**：每次 `--apply` 都会把旧权重存为 `weights.v<旧版本>.json`，然后 `version+1`；卡片的 `_trace.weights_version` 和 `runs.jsonl` 记录每次运行用的是哪一版。
- **确认**：`weekly_review.py --apply <proposals 文件> --confirm` 等价于手动把 `confirmed` 改成 `true`。同一份提议不能应用两次；如果权重在提议生成后被改过，应用会被拒绝。
- **回滚**：`weekly_review.py --state-dir inspiration --rollback` 撤销最近一次调整，也会写进历史。
