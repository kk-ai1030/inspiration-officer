# 反馈事件与权重

## 事件表（设计文档 §10b）

| 动作 | 中文 | 权重 | 显式 | 卡片状态 | 副作用 |
|---|---|---|---|---|---|
| `adopt` | 采纳 | +1.0 | 是 | adopted | — |
| `start_now` | 立刻动手（一小时内开始做） | +1.0 | 是 | adopted | — |
| `reject` | 否决 | −1.0 | 是 | rejected | 来源 ID 进负面清单 |
| `done` | 已做过 | −1.0 | 是 | done | 来源 ID 进负面清单 |
| `not_important` | 已读但不重要 | −0.5 ※ | 是 | dismissed | — |
| `edited` | 改写了卡片 | +0.8 | 是 | edited | 保存改动 diff |
| `ask_detail` | 追问细节 | +0.5 | 是 | 不变 | — |
| `read_no_action` | 已读无动作 | −0.2 | 否 | 不变 | — |
| `unread` | 未读 | −0.1 | 否 | 不变 | — |

※ 设计文档 §10b 的表里没有“已读但不重要”这一项，−0.5 是本实现的假设，可以在 `record_verdict.py` 的 `ACTIONS` 中修改。

## 显式和隐式信号分开用

- **显式信号**（用户主动点的）参与周度权重提议。
- **隐式信号**（未读、已读无动作）**只用来发现模式，不直接改权重**。“没读”可能只是推送时间不对。发现模式后，在周报里用一句话问用户确认：“我注意到你最近更常接受优化类建议，是这个方向吗？”

## 一条 verdict 记录的样子

```json
{"ts": "2026-10-28T08:10:00+08:00", "card_id": "ins_20261028_001", "source_ref": "2610.30755v1",
 "type": "knowledge", "action": "adopt", "label": "采纳", "weight": 1.0, "explicit": true,
 "reason": "正好要补基线", "rubric_rule_ids": ["R01", "R02", "R07"]}
```

`rubric_rule_ids` 用来在周报里统计“哪条准则打高分的卡片最常被否决”，从而定位出问题的准则。
