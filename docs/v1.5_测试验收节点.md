> 适用：Windows，从 1.4.5-weakbeta（组员包）升级。每个节点都写明 **输入 → 命令 → 期望输出 → 通过判据 → 失败时交什么**。

```mermaid

  P0[P0 升级与离线回归] --> P1[P1 建资料库]
```

## P0 升级与离线回归

- **输入**：解压后的 `inspiration-skills-v1.5.0-test\`；旧目录里的 `config.json`、`platform_ids.json`、`inspiration\`。
- **命令**
  ```powershell
  # 把旧目录的 config.json、platform_ids.json、inspiration\ 复制到新目录后：
  python scripts\selfcheck.py package
  python scripts\selfcheck.py g1
  python platform\setup_platform.py --config config.json --replace
  python platform\setup_platform.py --config config.json --check
  ```
- **期望**：`package` 全部 OK；`g1` 最后一行是通过，其中有一组“本地观察 O1–O15（v1.5）”；`--check` 显示 7 个技能已导入、灵感官绑定正常。
- **通过判据**：三条命令都没有 FAIL。
- **失败时**：`python platform\collect_feedback.py --test P0 --run "python scripts\selfcheck.py g1"`。

## P1 建资料库

- **输入**：你真实的代码（至少一个包含几百行的项目）、一份运行日志、一份笔记。
- **命令**
  ```powershell
  python platform\observe.py --config config.json init
  ```
  然后把资料放进 `library\code`、`library\logs`、`library\notes`（`papers`、`data` 可选）；大仓库在 `config.json → observe.roots` 写原路径（见用户手册 F10）。
- **期望**：生成 `library\` 和五个子文件夹，命令打印出配置说明。
- **通过判据**：`config.json` 里有 `observe` 段（没有就从 `platform\config.example.json` 复制）。

## P2 扫描与预览

- **命令**
  ```powershell
  python platform\observe.py --config config.json scan
  type inspiration\library\summary.md
  python platform\observe.py --config config.json list --all
  python platform\observe.py --config config.json show <list 里的一个 obs_编号>
  ```
- **期望**
  1. `scan` 打印每个观察者一行统计（code / logs / notes / papers / usage），最后一行 `observed.jsonl：N 条`。
  2. `list` 显示“入围 ≤ 6 条”，A 类最多 3 条；`--all` 会给出未入围的原因（低于门槛、超过配额…）。
  3. `show` 能看到证据原文（带行号）和 `library://<label>/...` 位置。
- **通过判据（人工判断，逐条打勾）**
  - ☐ 扫描在 3 分钟内结束，没有报错退出（某个观察者写“跳过：…”可以接受，但要记下来）
  - ☐ 入围的发现里，至少一半你认为“确实值得看一眼”
  - ☐ 证据里**没有**出现你电脑上的绝对路径（盘符开头的完整路径）或密钥（证据位置应是 `library://` 开头）
- **失败时**：把 `inspiration\library\summary.md` 和 `list --all` 的输出脱敏后放进反馈；`collect_feedback.py --test P2`。

## P3 云端跑一次（观察通道的端到端）

- **命令**：打开评价页 → 点“跑一次灵感”。（或者在网页里对灵感官说：“主动探索灵感，只看本地观察”）
  ```powershell
  python platform\review_server.py --config config.json --open
  ```
- **期望**
  1. 收货员（评价页的命令行窗口）先打印一行 `本地观察：observed.jsonl N 条（新 …）`，再上传状态（附件里有 `observed.jsonl`）。
  2. 网页会话里 prepare 输出有 `OBSERVED n`（n ≥ 1）；沙箱里出现 `/workspace/inspiration_out/obs_*.md`。
  3. 最终有 ≥ 1 张卡片带“本地观察 ·…”标签；引文是你的代码行 / 日志行 / 笔记原句。
  4. 网页显示 completed（不是“任务已中断”）。
- **通过判据**：☐ 观察型卡片入库并出现在评价页 ☐ 引文能在你的文件里逐字找到 ☐ `numbers_provenance` 里是 `observed`。
- **记录**：运行用了多久、`python scripts\selfcheck.py skills --config config.json` 的 loaded 字段。
- **失败时**：`python platform\collect_feedback.py --test P3 --run "python platform\receiver.py --config config.json --once"`；附上会话链接。

## P4 评价与不重复

- **命令**：评价页里对一张观察型卡片选“否决”，另一张选“采纳”；然后
  ```powershell
  python platform\observe.py --config config.json scan
  python platform\observe.py --config config.json list --all
  ```
- **期望**：这两条的 `obs_` 编号**不再入围**（原因显示已推送 / 负面清单）。
- **通过判据**：☐ 两条都不在入围里 ☐ `python scripts\selfcheck.py g4 --state inspiration --config config.json` 通过。

## P5 修好后自动消失

- **命令**：挑一条代码类发现（比如“XX 过长”），把那个函数拆短，或者把那份日志移出 `library\logs`；然后
  ```powershell
  python platform\observe.py --config config.json scan
  ```
- **期望**：`scan` 最后一行“已消失 ≥ 1”；`inspiration\library\observed_history.jsonl` 里多一行，标记为已解决。
- **通过判据**：☐ 该发现不在 `observed.jsonl` 里了。

## P6 隐私与打包

- **命令**
  ```powershell
  git status --short            # 若你用 Git 协作
  python scripts\selfcheck.py g5
  ```
- **期望**：`library\`、`inspiration\observed.jsonl` 不出现在 `git status` 里；`g5` 通过。
- **通过判据**：☐ 两项都满足。

## 已知问题（不阻塞 Beta）

| 编号 | 现象 | 怎么办 |
|---|---|---|
| K13 | 扫描目录指向大量说明文档时，规则句子可能被当成“待查 / 反常”笔记 | notes 只放自己的笔记；或者用 `observe.exclude_globs` 排除 |
| K14 | 读会话标题需要会话令牌；没有就跳过（usage 一行会写“已关闭 / 403”） | 不影响其它观察者 |
| K15 | 观察型卡片的 `minimal_check` 由模型写，质量取决于证据片段长度 | 嫌证据不够就调大 `observe.snippet_lines`（会多上传一些代码） |
