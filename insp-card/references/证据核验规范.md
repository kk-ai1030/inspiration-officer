# 证据核验规范

测评报告最重要的判断：**SciencePal = 可以被审计的执行器 + 仍需校验的解释器。** 所以卡片的每一条事实都必须能被脚本重新核对，而不是靠 agent 自述。

## 外部校验器会检查什么

| 检查 | 方法 | 不通过时 |
|---|---|---|
| 引用存在 | `verify_arxiv.py` 打开 `arxiv.org/abs/<id>`，比对 `citation_title` 与 triage 中的标题 | 卡片丢弃 |
| 候选有原文（仅全文模式） | 编排器抓取 arXiv HTML（失败用 PDF）+ 至少 1 篇相关文献原文；拿不到就不出卡，下次重试，最多 3 次 | 候选移出 shortlisted |
| quote 是逐字片段 | 规范化后做子串匹配（摘要或原文） | 卡片丢弃 |
| 原文引文真实（仅全文模式） | `fulltext_quotes` 每条都是 `ft_<ID>.md` 的子串，section 是真实章节，至少 1 条不在摘要里 | 卡片丢弃 |
| 相关文献引文真实 | `related_evidence` 的 ref 在附件里，quote 是 `rel_<ID>.md` 的子串 | 卡片丢弃 |
| 数字有出处 | 小数和百分数必须出现在摘要里，或登记为 `fulltext:<ID>`（在该原文中可找到）/ `executed:` | 卡片丢弃 |
| 引用不越界 | `source.ref` 必须在本次 shortlisted 中 | 卡片丢弃 |
| 不重复 | 不在 `state.pushed`、不在负面清单 | 卡片丢弃 |
| 技能确实被加载 | 根节点 `flow_version` + 平台 `agent-run/skills` 的 `loaded` 字段 | 整批丢弃 |

## agent 自己要做的事

1. 写 quote / fulltext_quotes / related_evidence 时直接从附件文件**复制**，不要凭理解复述。
2. 每写一个数字，就在 `numbers_provenance` 里登记一条。
3. `source.verified` 只有在你本次运行中实际打开过 arXiv 页面并核对标题时才填 `true`，否则填 `false`。填 `false` 不会扣分，乱填 `true` 会被校验器发现。
4. 不要对“这份文件是哪次会话生成的”之类的来源问题做推断。测评里出现过模型用 `created_at` 反推来源、结论自信但错误的情况。来源只信平台字段（thread_id / agent_run_id）。

## 读取模式与链接（v1.4.1）

- `config.json` 的 `arxiv_fetch_mode` 默认 `abstract`：证据只到摘要层，`source.quote` 必须是摘要逐字片段，不核对原文。
- 改成 `fulltext` 才启用下面“证据到原文层”的全部检查。
- 两种模式下，校验通过的卡片都由脚本写入链接：`source.url`（arXiv 摘要页）、`source.pdf_url`、`source.read_mode`；全文模式另写 `source.fulltext_url`（实际读到的 HTML 或 PDF）。模型写的链接一律被覆盖。

## 证据到原文层（v1.3；仅 `arxiv_fetch_mode = fulltext`）

旧版只核对到摘要，卡片很容易变成“摘要复述 + 想象”。v1.3 起编排器在出卡前抓取候选论文全文和相关文献全文，并作为附件提供：

| 附件 | 内容 |
|---|---|
| `ft_<ID>.md` | 候选论文全文（arXiv HTML 转文本，`#` 开头的行是章节标题，公式写成 `$...$`） |
| `rel_<ID>.md` | 相关文献全文：一部分来自候选论文参考文献里的 arXiv 条目（relation 提示 cited），一部分来自 arXiv 关键词检索（search） |
| `fulltext_index.json` | 候选 → 原文文件、章节列表、相关文献清单 |

卡片里可以写“论文第 4 节表明……”，但必须在 `fulltext_quotes` 里给出那一节的逐字引文。附件里没有的论文一律不能引用。
