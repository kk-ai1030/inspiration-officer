# 灵感卡片契约

## 字段表

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | string | `ins_YYYYMMDD_NNN`，日期为生成日，NNN 从 001 起 |
| `type` | enum | `optimization` / `knowledge` / `hypothesis` / `process` |
| `created_at` | string | ISO 8601，带时区 |
| `source.kind` | string | `arxiv` / `log` / `anomaly` / `workspace` |
| `source.ref` | string | 必须是 `triage.json.shortlisted[].id` 之一（可带版本号） |
| `source.quote` | string | 摘要或原文逐字片段，6–60 词；多段用 `...` 连接 |
| `source.fulltext_quotes` | array | **仅 `fetch_mode = fulltext` 必填**（摘要模式不写）。1–4 条 `{quote, section}`：quote 是 `ft_<ID>.md` 的逐字片段（8–80 词），section 是原文真实章节标题（不能是 Abstract）；至少 1 条不在摘要里 |
| `source.url` / `source.pdf_url` / `source.read_mode` / `source.fulltext_url` | string | **由校验脚本写入，agent 不写**：摘要页链接、PDF 链接、`abstract`/`fulltext`、（全文模式）实际读过的全文链接 |
| `source.verified` | bool | agent 只能填 `false`，或在实际打开 arXiv 页面核对过标题后填 `true`；外部校验器会重新核验 |
| `title` | string | 一句话标题 |
| `one_line` | string | ≤ 40 字 |
| `why_me` | string | 对照用户当前项目说明“为什么是我” |
| `hypothesis` | string | `hypothesis` 型必填；其它类型可为空字符串 |
| `minimal_check` | string | 两天内能完成的最小验证动作，写到可以直接执行的程度 |
| `expected_observable` | string | 预期看到什么、判据是什么 |
| `falsifier` | string | 什么结果说明想法不成立 |
| `magnitude` | string | 关键量的量级，数字必须有出处 |
| `cost_estimate` | object | `{tokens, wall_clock, risk}`，risk ∈ low / medium / high |
| `rubric_scores` | array | 3–5 条 `{rule_id, score(1–5 整数), reason}` |
| `related_evidence` | array | **仅 `fetch_mode = fulltext` 必填**（摘要模式写空数组或省略）。≥1 条 `{ref, relation, quote, why}`：ref 必须是附件 `fulltext_index.json` 里的相关文献；relation ∈ supports / contradicts / extends / method / baseline / context；quote 是 `rel_<ID>.md` 的逐字片段（6–80 词） |
| `numbers_provenance` | array | `{value, source}`，source 是 `abstract`、`fulltext:<arXiv ID>` 或 `executed:<命令或文件>`；没有数字时为空数组 |
| `action_brief` | object | **可选**（v1.5.1）。动手单 7 栏：`scene/params/method/output/baseline/criterion/deliverables`；params 每项 `{name,value,unit,source}`，source ∈ library / observed / user。不合格时校验脚本删掉此字段并写 `_brief_dropped`，卡片照常通过 |
| `status` | string | 固定为 `proposed` |
| `verdict` | null | 固定为 `null` |

## 三个核心字段为什么不能省

- `minimal_check`：没有验证动作的灵感是噪声。用户看到卡片后只需要判断“这个动作值不值得做”。
- `falsifier`：说清什么结果会推翻它。这一条能过滤掉大量“听起来很对但没法检验”的漂亮话。
- `cost_estimate`：自己申报成本，抑制“需要三个月”的幻想型建议。

## 好卡片 vs 坏卡片

| | 坏 | 好 |
|---|---|---|
| one_line | “这篇论文很有启发” | “复杂记忆前先跑朴素 RAG 基线” |
| why_me | “与 AI 研究相关” | “我们正在设计经验记忆，但还没有一个朴素基线可以对比” |
| minimal_check | “深入研究一下” | “在现有 benchmark 上加一个原始历史 + 稠密检索的基线，跑一轮” |
| falsifier | （空） | “基线落后超过摘要报告的上限 5.53 分，则整合确有价值” |
| magnitude | “提升很大” | “摘要报告差距 0.13–5.53 分” |
