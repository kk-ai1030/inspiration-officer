# 逐条打分规范

**不做“一次性给总分”，而是逐条打分再加权。** 出错时能定位到“是第 7 条准则被过度使用了”，而不是面对一个没法调试的黑箱分数。

## 步骤

1. 读取附件 `rubric.md`，它是唯一的准则来源。**不要使用平台长期记忆中的准则副本**：测评已证明记忆会被召回，但不一定被执行，而且可能过期。
2. 对每个候选，挑出最相关的 3–5 条准则。R01（相关性）和 R07（可证伪）建议每次都选。
3. 每条给 1–5 的整数分和一句理由。理由必须指向候选的具体内容，不能只复述准则。
4. 平均分 < 3，或任一条为 1 分 → 写进 `rejected`，`rule_ids` 填拉低分数的准则。
5. 平均分乘以 `weights.json` 中该类型的权重（如果附件提供了），作为配额截断时的排序依据。

## 例子

```json
"rubric_scores": [
  {"rule_id": "R01", "score": 4, "reason": "摘要讨论的经验复用正是当前项目的核心问题"},
  {"rule_id": "R02", "score": 4, "reason": "给出四个 benchmark 上 0.13–5.53 分的差距区间"},
  {"rule_id": "R07", "score": 5, "reason": "加一个基线跑一轮即可得到是/否"}
]
```

## 被否决候选的理由

理由必须引用准则编号，并写出具体原因，例如：

- `R02`：摘要没有给出可独立复现的单一判据，属于听起来对但难检验。
- `R11`：去掉形容词以后，没有剩下可以检验的主张。
- `R14`：超出 hypothesis 周配额。
