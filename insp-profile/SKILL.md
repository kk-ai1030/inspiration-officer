# 用户画像访谈

## 定位

画像相当于“系统级 AGENT.md”：让灵感官不用每次提醒，也知道用户是谁、会什么、不会什么、关注什么。它决定了两件事：

1. **每次跑灵感用什么检索式**（arXiv 分类 + 关键词 → `[灵感配置]` 记忆）；
2. **卡片用什么深度跟用户说话**（擅长 / 不熟 / 不要假设我会）。

本 Skill 只负责**访谈 → 预览 → 确认 → 交付**。文件落盘、记忆同步由本地收货员完成，本 Skill 不直接写平台记忆。

## 必读规范

- [画像契约.md](references/画像契约.md)

## 硬纪律（加载后先原文复述）

1. 没有具体例子的“擅长”不算擅长；兴趣不能推断成能力。
2. 用户没有回复“确认”之前，不写 profile.json，也不输出结果块。
3. 用普通对话提问，不调用 ask 或任何弹表单的工具。

## 强制流程

### 0. 看有没有旧画像

在已召回的记忆里找以 `[灵感画像]` 开头的条目：

- **有**：先用 3–5 行复述现有画像，问“哪些要改？”，只针对要改的部分追问（更新模式）。没提到的部分按旧画像原样保留，把它们也写进 answers。
- **没有**：进入第 1 步，完整访谈。

### 1. 一次问完 7 个问题

用**一条消息**发出下面 7 个问题，告诉用户“简短回答即可，不知道的可以跳过”：

1. 你的身份与研究领域？当前在做的项目用一句话说。
2. 最近最关注的 2–4 个方向？（只代表兴趣，不代表你会）
3. 你擅长的技术或方法？**每项请举一个做过的例子**。
4. 你不熟、需要我先给定义再给结论的领域？
5. 表达偏好？（语言、结论先行、表格、详略……）
6. 希望我每次看哪些 arXiv 分类和关键词？不确定可以说“你帮我定”。
7. 有什么“不要假设我会”的东西，或者明确不想看的方向？

### 2. 最多追问一轮

只在缺**必填项**时追问，一次问完：

| 缺什么 | 怎么办 |
|---|---|
| 身份 / 项目 | 必须追问 |
| 关注方向 | 必须追问 |
| 擅长没有给例子 | 问一次“能举个例子吗？”；仍然没有就按“了解”处理（脚本会自动降级） |
| 用户说“你帮我定”分类和关键词 | 根据领域提议 1–3 个 arXiv 分类和 3–6 个英文关键词，写进预览让用户确认 |

### 3. 写 answers 并预览

把回答整理成 `/workspace/inspiration_out/profile_answers.json`（格式见画像契约），**尽量用用户的原话**，不要拔高。然后运行：

```bash
python3 /workspace/skills/insp-profile/scripts/build_profile.py --preview
```

找不到路径时：`find / -name build_profile.py -path "*insp-profile*" 2>/dev/null | head -1`。

- 退出码 2：按 `PROFILE_INVALID` 的提示补问用户，改 answers 后重跑；
- 退出码 0：把 `PREVIEW` 的内容原样发给用户，最后问：“回复‘确认’保存，或者告诉我要改哪里。”

### 4. 用户确认后交付

用户回复“确认”（或“可以 / 没问题 / 保存”等明确同意）后运行：

```bash
python3 /workspace/skills/insp-profile/scripts/build_profile.py --confirmed
```

最终回答 = 一句话说明（“画像已生成，本地收货员会在 1 分钟内落盘并同步记忆”）+ 脚本打印的整个 `<<<INSP_PROFILE_JSON ... INSP_PROFILE_JSON>>>` 结果块，**原样、不改动**。然后直接结束回答：**不要调用 `complete`（交付）工具，也不要放附件**——结果块属于正文；万一平台提示 `delivery_attachments_required`，`attachments` 里只能放真实文件路径，补一次仍失败就直接结束。

用户要求修改时：改 answers → 回到第 3 步重新预览。

## 停止条件

- 用户中途说“算了 / 下次再说”：不写任何文件，回复一句“好的，随时可以说‘建立画像’继续”。
- 用户拒绝提供任何信息：不编造画像；说明“没有画像时，卡片会写‘未提供画像，相关性只基于关键词’”。
