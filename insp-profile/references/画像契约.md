# 画像契约（insp-profile/1.0）

## 1. 三个文件的关系

| 文件 | 谁写 | 用途 |
|---|---|---|
| `/workspace/inspiration_out/profile_answers.json` | agent（访谈整理） | 访谈回答的草稿，可反复修改 |
| `/workspace/inspiration_out/profile.json` | `build_profile.py --confirmed` | 用户确认后的画像，收货员只认这个文件 |
| 本地 `inspiration/profile/{profile.json, AGENT.md, interests.md, claims.md}` | 本地收货员（调用 `profile_tool.apply_profile`） | **权威副本**，有历史版本，可以 diff 和回滚 |
| 平台记忆 `[灵感画像] …`、`[灵感配置] …` | 本地收货员（需要会话令牌） | 5–8 条一句话投影，每次运行自动召回 |

**文件是权威，记忆是投影。** 测评已证明记忆会被召回，但不一定被执行；所以画像的完整版放在文件里，记忆里只放能一眼读懂的摘要。

## 2. answers 格式

```json
{
  "identity": "物理系博三，做中性原子量子计算实验；项目是 Rydberg 门保真度优化",
  "interests": [{"topic": "量子纠错", "why": "下一步要做"}, "中性原子阵列"],
  "strengths": [{"item": "Python 数据分析", "evidence": "写过整套采集-拟合脚本"}],
  "gaps": ["量子纠错编码理论", {"item": "深度学习训练细节", "need": "先给直觉再给公式"}],
  "knowledge_levels": [{"area": "表面码", "level": "入门"}],
  "preferences": "中文；结论先行；能表格就表格",
  "arxiv_categories": ["quant-ph", "physics.atom-ph"],
  "keywords": ["Rydberg", "neutral atom"],
  "do_not_assume": ["不要假设我会 C++"]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `identity` | 是 | 一句话：身份 + 领域 + 当前项目 |
| `interests` | 是（≥1） | 字符串或 `{topic, why}`；只代表兴趣 |
| `strengths` | 否 | 每条必须有 `evidence`（做过的具体例子）；没有例子的会被降级为 `knowledge_levels` 里的“了解” |
| `gaps` | 否 | 字符串或 `{item, need}`；`need` 默认是“先给定义再给结论” |
| `knowledge_levels` | 否 | `level` ∈ 熟练 / 能用 / 了解 / 入门 / 不会 |
| `preferences` | 否 | 一句话或分号分隔 |
| `arxiv_categories`、`keywords` | 至少一个 | 分类形如 `quant-ph`、`cs.LG`；关键词用英文（arXiv 摘要是英文） |
| `do_not_assume` | 否 | 不要假设会的东西、不想看的方向 |

## 3. 生成的 profile.json

在 answers 的基础上，脚本会补上：`schema: "insp-profile/1.0"`、`updated_at`、`sources.arxiv_query`（由分类和关键词拼成的 arXiv 检索式）、`provenance: {"via": "insp-profile", "confirmed_in_chat": true}`。

本地校验规则（`profile_tool.check`）：`schema` 正确；`identity.summary` 非空；`interests`、`strengths`、`gaps` 是数组；每条 strengths 都有 `item` 和 `evidence`；`knowledge_levels.level` 合法。不合格的画像会被收货员拒收，本地文件不变。

## 4. 落盘之后会发生什么

1. 本地 `state.json` 里 arXiv 来源的检索式会被替换成 `sources.arxiv_query`，关键词也会同步更新；
2. 记忆投影整体替换（删除所有带 `insp-profile` 标签的旧条目，再写入新条目）；
3. 旧版 `profile.json` 备份到 `profile/history/`；
4. 评价页弹出“用户画像已更新”的通知。

## 5. 平台自动抽取的记忆

平台会在每次运行结束时自动抽取记忆（`source.kind=auto_extraction`），常常把一次性的约束误当成长期偏好。规则是：

- 自动抽取的条目**不是画像**，灵感官不得把它当成画像使用；
- 用户可以在本地运行 `profile_tool.py --audit-memory` 逐条查看，`--promote <ID>` 确认后并入画像，`--drop <ID>` 删除。
