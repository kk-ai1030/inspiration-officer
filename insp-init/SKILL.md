# 灵感状态初始化与回读

## 定位

“它忘了上次跑到哪”是这类系统的头号病症。本 Skill 负责建立和检查灵感机制的唯一权威状态。它不产生灵感，只回答三个问题：**状态在哪、状态是否完整、下一次运行能不能安全开始。**

## 必读规范

- [状态契约.md](references/状态契约.md)
- [三源画像规范.md](references/三源画像规范.md)

## 运行流程

### 1. 判断模式

| 情况 | 模式 |
|---|---|
| 没有 `inspiration/` 目录 | 新建：从 [状态模板](assets/灵感状态模板/inspiration/state.json) 复制整套模板 |
| 有目录、校验通过 | 回读：报告上次运行时间、已推送数量、配额使用、待处理反馈 |
| 有目录、校验失败 | 修复草案：列出缺失或损坏项，**不自动修复** |

### 2. 新建时必须问清的四件事

新建时先在对话中给出草案，用户确认后才写入：

1. 关注方向：`state.json.sources`（arXiv 分类或检索词）和 `keywords`（用于相关性粗打分）。
2. 当前项目一句话描述：写入 `profile/interests.md`，卡片的 `why_me` 必须对照它。
3. 用户**有证据**的能力：写入 `profile/claims.md`。没有证据的能力一律不写。
4. 是否首次运行：首次运行时把 `bootstrap` 设为 `true`，允许把第一批条目全部视为新增；第一次运行成功后编排器会自动设回 `false`。

### 3. 校验

写入或回读后运行：

```bash
python3 <insp-init 目录>/scripts/validate_insp_state.py <状态根目录>/inspiration
```

校验不通过时，状态保持“不可运行”，不得交给 insp-nightly。

### 4. 平台记忆的分工

打分准则（rubric）**不放进平台长期记忆**。测评已证明记忆“会被召回、但不一定被执行”。分工如下：

| 内容 | 放在哪 |
|---|---|
| 硬规则（来源校验、字段齐全、配额、负面清单） | 校验脚本 + agent system prompt |
| 打分准则 | `taste/rubric.md`，每次运行作为附件显式提供 |
| 软偏好（格式、语气、关注方向） | 平台长期记忆，按“条件 → 动作”格式书写 |

## 停止条件

状态目录校验未通过、用户未确认草案、或画像里出现没有证据的能力声明时，停止写入并报告。不得替用户编造兴趣、能力或历史评价。
