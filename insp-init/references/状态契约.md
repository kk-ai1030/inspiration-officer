# 状态契约

## 目录结构

```text
inspiration/
├── state.json            # 唯一权威运行状态（编排器读写）
├── negative.jsonl        # 负面清单：命中即不再提（可为空文件，但必须存在）
├── verdicts.jsonl        # 用户评价日志（只追加）
├── runs.jsonl            # 每次运行的记录（只追加）
├── observed.jsonl        # v1.5 可选：本地观察者的发现（observed 通道输入，由用户电脑上的 observe 扫描生成）
├── taste/
│   ├── rubric.md         # 打分准则：## Rxx 标题 + 判断 / 正例 / 反例 / 出处
│   └── weights.json      # 当前权重（只由 weekly_review.py --apply 修改）
├── profile/
│   ├── interests.md      # 用户说过“我关注什么”
│   ├── claims.md         # 有证据的能力
│   └── observed.md       # 从用户的代码、数据中观察到的事实（附路径）
└── cards/
    └── YYYY-MM-DD/cards.json
```

## state.json 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | 当前为 `"1.0"` |
| `bootstrap` | bool | 只有为 `true` 时才允许空的 `seen_ids` |
| `last_run_at` | string / null | ISO 8601 时间 |
| `last_run_id` | string / null | 编排器生成的运行 ID |
| `sources` | array | `{kind:"arxiv", query:"cat:cs.CL AND abs:memory"}` 之类 |
| `keywords` | array | 相关性粗打分用的关键词，至少 1 个 |
| `seen_ids` | array | 所有看过的条目 ID（L0 增量依据） |
| `pushed` | array | `{id, card_id, title, type, pushed_at}`，已推送过的条目 |
| `quota` | object | 各类型配额，见下 |
| `quota_used` | object | `{"2026-10-28": {"optimization":1, ...}}` 按日期计数 |
| `triage` | object | 粗打分门槛与上限 |
| `revival` | object | `{every: 20, counter: 0}`，被主题否决的条目每 20 次放行 1 次 |
| `observed` | object | v1.5 可选：observed 通道参数 `{enabled, per_type, max_total, min_severity, max_age_days}`；`per_type` 可以是数字或 `{类型: 条数}`，默认 A 类 3、其它 2，总数 6 |
| `library_arxiv_ids` | array | v1.5 可选：用户本地论文库里已有的 arXiv 编号（observe 扫描写入），按“已见过”处理，不会当新论文推送 |

## observed.jsonl（v1.5，可选）

每行一个发现，由本地观察者生成；沙箱里只读。

| 字段 | 说明 |
|---|---|
| `id` | `obs_` + 12 位十六进制，同一发现跨次扫描不变（去重靠它：推送后进 `pushed`，否决后进 `negative.jsonl`） |
| `kind` | `workspace`（代码 / 论文库）· `log`（笔记 / 使用记录）· `anomaly`（日志 / 数据反常） |
| `candidate_type` / `allowed_types` | 建议的卡片类型 / 允许的卡片类型（optimization · knowledge · hypothesis · process） |
| `severity` | 1–5，越高越值得看 |
| `title` / `summary` | 一句话标题 / 检测器说明 |
| `evidence` | 证据原文（代码片段、日志行、笔记原句、统计），已脱敏、最长约 1800 字符；卡片 quote 必须从这里逐字复制 |
| `evidence_ref` | 本地位置，`library://<根目录名>/<相对路径>#L起-L止`，不含绝对路径 |
| `detector` / `subfield` | 检测器（如 `code.long_function`）/ 子领域（code · logs · data · notes · papers · usage，参与 subfield 权重学习） |
| `first_seen` / `last_seen` / `times_seen` | 首次 / 最近一次发现时间，出现次数 |


## 配额（与设计文档 §8 一致）

```json
"quota": {
  "daily_total_max": 999,
  "optimization": {"per_day": 999},   // v1.5.1：A 类不设硬上限、不计入 daily_total_max
  "knowledge":    {"per_week": 999},
  "hypothesis":   {"per_week": 1},
  "process":      {"per_14_days": 2}
}
```

999 表示实际不限（v1.4 默认：knowledge 与每日总量）。

周的计算口径：以当天为终点往前数 7 天（含当天）。

## 负面清单 negative.jsonl

每行一个 JSON：

```json
{"kind": "id", "value": "2610.12345", "reason": "已做过", "added_at": "2026-10-20T09:00:00+08:00", "from_card": "ins_20261019_001"}
{"kind": "topic", "value": "agentic memory consolidation", "reason": "方向不感兴趣", "added_at": "...", "from_card": "..."}
```

- `kind=id`：命中即丢，没有复活机会。
- `kind=topic`：标题或摘要包含该短语即拦截，但受复活机制约束（§10f）。

## 所有权

| 文件 | 谁可以写 |
|---|---|
| `state.json`、`runs.jsonl` | 只有编排器 |
| `negative.jsonl`、`verdicts.jsonl` | 只有 `record_verdict.py` |
| `taste/weights.json` | 只有 `weekly_review.py --apply`，并且需要用户确认 |
| `taste/rubric.md`、`profile/*` | 只有用户本人，或用户确认过的修订 |
| `cards/` | 编排器（写入通过校验的卡片） |

agent 在平台沙箱里拿到的只是这些文件的**副本**，它修改副本不会影响权威状态。
