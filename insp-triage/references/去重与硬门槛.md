# 去重与硬门槛

不做去重，系统一周内就会被静音。三个层次（设计文档 §11）：

| 层次 | 规则 | 实现 |
|---|---|---|
| ID 级 | 推送过的 ID、负面清单 `kind=id` 的 ID：绝不再提 | `triage.py` L1-a |
| 语义级 | 标题与已推送标题或本批次标题的 Jaccard ≥ `title_similarity_threshold`（默认 0.6）就丢弃 | `triage.py` L1-d |
| 主题级 | 负面清单 `kind=topic` 的短语出现在标题或摘要中就拦截 | `triage.py` L1-b |

> Jaccard 是一个廉价的近似。以后可以换成向量相似度，但接口不变：输入两段文本，输出 0–1 之间的分数。

## 复活机制（设计文档 §10f）

被主题否决拦截的条目不是永久埋掉：`state.revival.counter` 每拦截一次加 1，每到 `revival.every`（默认 20）的倍数就放行一次，并在候选上标记 `revival: true`。insp-card 生成这类卡片时必须在 `why_me` 里写明“这是复活放行的条目，你之前否决过这个方向”。

`revival.every` 不允许设为 0 或 1。否则反馈闭环会退化成回音壁，系统只推用户本来就喜欢的东西。

## 硬门槛

| 门槛 | 理由 |
|---|---|
| 有 ID | 无法追溯的条目不能去重 |
| 有标题 | 同上 |
| 摘要 ≥ 30 词 | 摘要太短就没法做逐字引用，后续卡片必然无法通过证据校验 |

“和当前项目是否相关”由粗打分负责，不在硬门槛里判断。
