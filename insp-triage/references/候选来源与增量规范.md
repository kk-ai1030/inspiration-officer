# 候选来源与增量规范

## 四类候选来源（设计文档 §6 L0）

| 来源 | 当前实现 | 输入格式 |
|---|---|---|
| 新论文增量（arXiv / RSS / 文献工具） | `triage.py --fetch-arxiv`，或任意脚本产出 `raw_items.json` | `{id, title, abstract, url, published, source}` |
| 任务日志中的“以后可以试试 / 这里有点怪” | 由编排器用 grep 从日志中提取，`source="log"`，`id="log:<文件>:<行号>"` | 同上，`abstract` 填原句及上下文 |
| 计算 / 数据异常 | 用户自己的自检脚本产出，`source="anomaly"` | 同上，`abstract` 填异常描述和数值 |
| 工作区文件变化 | 编排器比较文件哈希，`source="workspace"`，`id="ws:<路径>:<sha8>"` | 同上，`abstract` 填变更摘要 |

第一阶段只接 arXiv，这也是默认行为（B2 之前唯一实现）。B2 起可在 `state.json` 顶层加 `candidate_sources` 段启用额外来源；产出同一格式后一起进同一个漏斗，去重 / 打分 / 配额规则不变：

```json
"candidate_sources": {
  "enabled": false,
  "arxiv": true,
  "providers": [
    {"kind": "rss", "url": "https://example.org/feed.xml", "limit": 20},
    {"kind": "openalex", "query": "surface code decoder", "limit": 20},
    {"kind": "semantic_scholar", "query": "neutral atom", "limit": 20},
    {"kind": "fixture", "path": "extra_sources.json"}
  ]
}
```

- `enabled=false` 或缺省整段：完全不联网，arXiv 路径逐字不变；
- `arxiv=false`：本轮只走额外来源，跳过 arXiv 可达性检查，不会被误判为 `FETCH_BLOCKED`；
- 所有 ID 带来源前缀（`rss:` / `oa:` / `s2:` / `fx:`），`url` 必填；同 DOI / URL 在合入前先去重；
- 摘要仍受 L0 的「至少 30 词」门槛，不因为换了来源就补字或放宽；`published` 归一为 `YYYY-MM-DD`；
- 单个来源抓取失败只跳过该来源并记一条 note，不中断整轮；
- 适配器实现在 nightly 技能自带的 `extra_sources` 模块里，随技能包一起进沙箱；离线 / 本地兜底可用 prepare 的 `--extra-raw` 直接读一份条目文件。

## 增量规则

1. ID 比较前去掉版本号（`2610.30755v1` 与 `2610.30755v2` 视为同一条）。
2. 本次运行中所有出现过的新 ID 写入 `triage.json.new_ids`。只有当整次运行**成功结束**（卡片通过校验，或结果为 `NO_CANDIDATES`）时，编排器才把它们并入 `state.seen_ids`。
3. 运行失败（`VALIDATION_FAILED`、agent 超时）时**不更新** `seen_ids`，下次运行会重新看到这些条目。这样做的代价是多花一次钱，换来的是不漏掉内容。
4. `bootstrap=true` 时 `seen_ids` 允许为空；首次成功运行后编排器把它设为 `false`。

## 限流

测评中 arXiv API 对单机出现过 429。处理顺序：

1. 等待后重试一次（编排器负责）；
2. 仍然失败则本晚以退出码 4 结束，记录到 `runs.jsonl`；
3. **不得**让 agent 用网页搜索或记忆“补”论文：补来的条目无法与快照对齐，会破坏增量计数。
