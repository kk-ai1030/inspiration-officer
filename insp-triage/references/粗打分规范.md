# 粗打分规范

粗打分的目的是**便宜地砍掉明显不相关的条目**，不是判断价值。价值判断留给 L2 的逐条 rubric 打分。

| 维度 | 1–5 分的计算（triage.py 当前实现） | 含义 |
|---|---|---|
| relevance | 无关键词命中为 1；否则 `min(5, 2 + 命中数)`，标题命中额外 +1 | 和 `state.keywords` 的重合程度 |
| actionability | `min(5, 2 + 动作词命中数)`，动作词如 code / github / benchmark / dataset / released | 是否有可以动手的抓手 |
| cost | `min(5, 2 + 低成本词命中数)`，如 training-free / simple / baseline / lightweight；5 = 最便宜 | 验证成本的粗略信号 |
| total | `0.5·relevance + 0.3·actionability + 0.2·cost` | 排序用 |

门槛：`relevance < state.triage.min_relevance`（默认 3）直接丢弃；复活条目豁免这条门槛。排序后只取前 `max_shortlist`（默认 8）条。

## 调参纪律

- 关键词写在 `state.keywords`，改一行就生效。
- **一次只改一个参数**（关键词、门槛、上限三者之一），并在 `runs.jsonl` 里记一笔，否则指标变了也不知道是谁的功劳。
- 不要为了让卡片变多而放宽门槛。设计文档 §20.7：数量永远不是指标。
